# Android Build Failure — Root Cause & Dependency Audit

**Date:** 2026-11-24
**Project:** `milonext / frontend` (local checkout: `/home/adii/Projects/miloverse/frontend`)
**CI command:** `cd android && ./gradlew assembleDebug --console=plain`
**Failing task:** `:app:checkDebugDuplicateClasses`

---

## 1. Executive summary

1. **Build blocker:** `kotlin-stdlib:1.8.22` and `kotlin-stdlib-jdk7/jdk8:1.6.21` are both on the
   app's runtime classpath. Since Kotlin 1.8, the JDK extension classes live *inside*
   `kotlin-stdlib`, so having the legacy split artifacts as well produces
   `Duplicate class kotlin.collections.jdk8.CollectionsJDK8Kt …` etc.
2. **Where the old jars come from:** `kotlinx-coroutines-android:1.6.4` (pulled in transitively by
   `androidx.lifecycle:lifecycle-common:2.6.2`). Coroutines 1.6.4 declares
   `kotlin-stdlib-jdk8:1.6.21` + `kotlin-stdlib-jdk7:1.6.21`.
3. **Why local passes but CI fails:** the exclude fix already exists in the **working tree** but is
   **uncommitted** (`git status` → ` M android/app/build.gradle`). CI checks out committed code,
   builds the version *without* the fix, and fails. A local `clean assembleDebug --rerun-tasks`
   with the fix passes (190 tasks executed).
4. **Immediate action:** commit `android/app/build.gradle`. Optionally apply the cleaner
   root-cause fix in §4.

Duplicate classes reported by AGP include:
`kotlin.collections.jdk8.CollectionsJDK8Kt`, `kotlin.internal.jdk7.JDK7PlatformImplementations`,

### Why the local build is green

`git status --short` → ` M android/app/build.gradle`. The working tree contains:

```groovy
configurations.all {
    exclude group: 'org.jetbrains.kotlin', module: 'kotlin-stdlib-jdk7'
    exclude group: 'org.jetbrains.kotlin', module: 'kotlin-stdlib-jdk8'
}
```

With this, `dependencyInsight` reports **"No dependencies matching given input were found"**
and `./gradlew clean assembleDebug --rerun-tasks` succeeds. CI never sees these lines because
the file was not committed.

## 4. Changes applied (2026-11-24)

All fixes below are in the working tree and **uncommitted**.

### `android/app/build.gradle`

- Removed the unused `flatDir` repository block and the redundant `constraints` block.
- Replaced the blanket exclude-only fix with the root-cause fix plus safety net:

```groovy
configurations.all {
    exclude group: 'org.jetbrains.kotlin', module: 'kotlin-stdlib-jdk7'
    exclude group: 'org.jetbrains.kotlin', module: 'kotlin-stdlib-jdk8'

    resolutionStrategy {
        force 'org.jetbrains.kotlinx:kotlinx-coroutines-android:1.8.1'
        force 'org.jetbrains.kotlinx:kotlinx-coroutines-core-jvm:1.8.1'
    }
}
```

Resolved result: `kotlinx-coroutines-android:1.8.1` (was 1.6.4) and
`kotlin-stdlib:1.9.21` for every requester (was a 1.6.21/1.7.10/1.8.10/1.8.22 mix).

### `android/app/src/main/java/com/onechat/app/MediaPlaybackService.java`

- Added `startMediaForeground(Notification)` helper using the typed 3-arg call on API 29+,
  with a fallback to the 2-arg call on API 24–28; used at all 4 start sites.
- Replaced all 3 `stopForeground(true)` calls with `stopForeground(STOP_FOREGROUND_REMOVE)`.
- Annotated the legacy audio-focus methods with `@SuppressWarnings("deprecation")` and a
  comment explaining they are required for API 24/25.

### `android/app/src/main/AndroidManifest.xml`

- Registered the service (it was missing entirely, so native playback could not work):

```xml
<service
    android:name=".MediaPlaybackService"
    android:exported="false"
    android:foregroundServiceType="mediaPlayback" />
```

### `frontend/package.json` + `pnpm-lock.yaml`

- Removed the deprecated `@studio-freight/lenis`. Application code already uses `lenis`, so no
  source changes were required.

### Remaining manual step

**Commit the changes** so CI picks them up. This is the only thing standing between the current
working tree and a green CI build. All changes were intentionally left uncommitted.

## 6. Decision record

- The duplicate-class failure is **not** caused by the Jam code; it is a pre-existing
  dependency-resolution problem in the committed Android build files.
- CI was red while local builds were green solely because the fix existed only in the working
  tree. A commit is still required.
- The root cause is fixed at the source (coroutines 1.8.1 no longer requests the legacy
  artifacts); the excludes remain as a safety net.
- `startForeground(int, Notification)` was **not** actually deprecated — the real deprecations
  were `stopForeground(boolean)` (3 sites) and the legacy audio-focus overloads (2 sites).
  The typed foreground-service call was still applied for Android 14 compliance.
- The missing `<service>` manifest registration was found during implementation and fixed; it
  was not part of the original audit.
- AGP/Gradle/SDK upgrades remain **out of scope** for this fix and are tracked as a separate
  migration.
- All changes remain **uncommitted** as requested.
